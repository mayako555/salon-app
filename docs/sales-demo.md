# 営業・説明用デモ

## 開き方

アプリの `/demo` を開く。ログイン不要。デモ基準日は2026年9月30日で固定し、2025年10月〜2026年9月の12か月を表示。1,340名の架空顧客、3名の架空スタッフ、3,000件以上の施術記録、84件の経費。データは決定的に生成し、氏名は架空の組合せ、電話番号は `090-XXXX-...`、実際のLINE ID・顧客データは含めない。

ダッシュボード→「AIに『なぜ？』と聞く」→顧客・スタッフ分析→CSV模擬取込みが推奨の説明順。予約・顧客・スタッフ・経費の追加や予約変更／キャンセルはReactメモリ内のみ。「デモをリセット」またはページ再読み込みで復元される。CSVは実ファイルを一切選択・読み取りしない。LINE・会計連携は外部認証や送信なしの模擬操作。

## 分離設計

- `/demo` およびその配下の表示境界だけが専用UI。`?demo=true` 等では有効にならない。通常のAuthProvider・認証Server Actions・通常APIを変更／迂回しない。
- RootLayout配下のRuntimeShellがパスを判定し、通常ページのみProductionShellを動的に読み込む。デモではAuthProvider、Firestore、トラッキング、通常のAI、フィードバックをマウントしない。
- デモの画面とデータモジュールにはFirebase・認証・Server Actions・外部サービスのimport、fetch、Storage呼出しなし。
- `/demo` 専用HTTPヘッダーで `connect-src 'none'`、`form-action 'none'`、`frame-src 'none'` 等を指定。外部／本番API通信をブラウザで禁止。通常ページには適用しない。
- 既存のCard/Button/Input/Dialog、ExecutiveSummary、Recharts、共通CSSを再利用。認証やAPI呼出しと結合したSidebar・業務ページは直接再利用せず、同じ配色・構成でデモ専用操作を用意。
- ExecutiveSummaryに省略可能なprofit/projectionを追加。通常画面の既存表示は、省略時に従来どおり。
- DB変更・本番データ生成・コピー・外部API鍵は不要。

## データとAI

9月売上242万円、8月250万円、前月比−3.2%。来店310件／320件、新規は各100件、再来210件／220件。9月経費136万2,800円、差額105万7,200円。スタッフ・メニュー別売上と月間合計は同じ記録から集計。

30日以内再来率42%→34%は営業説明用の固定分析シナリオ。AIは事前作成したサンプル回答で、推論や外部通信をしない。画面にも明記し、実AI実行やローカル変更の再分析を装わない。

## 追加画面（2026-10-01）

- 評価制度・育成：本番の `evaluations/shared.ts` のテンプレート／採点処理を共有。四半期選択、評価入力、下書き／確定、コメント、成長カルテをデモ内で操作できる。
- 高度分析：本番に合わせた11タブ。月次・スタッフ・メニューはデモ記録から集計。紹介・回帰・予測・LTV等は固定シナリオと明記し、実モデルを呼ばない。店舗比較の複数店舗例も実集計と区別する。
- 給与・報酬計算：給与一覧・支給控除・明細・模擬確定。固定サンプルで税額計算・振込なし。評価・給与の変更は画面移動中も保持し、デモリセットで破棄。
- ブラウザで評価下書き保存・成長カルテ・給与確定・分析全タブを確認。187テスト、型検査、本番ビルドが成功。
