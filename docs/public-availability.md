# お客様向け空き状況リンク

設定 → お客様向けの空き状況リンク。店舗オーナー／管理者が店舗別に施術時間、受付時間、同時施術人数、直前枠除外時間を設定し、公開を有効にして保存する。初期状態は非公開。リンクのコピーとQR表示に対応。ネット予約受付は既存設定ではOFF。店舗管理者が明示的にONにして保存する。全てのお客様に同じリンクを配布でき、ログイン不要。公開停止で既存リンクを無効化、再発行で旧リンクを失効する。

## 表示と制約

- 日本時間の今日から14日分を7日ずつ表示。30分刻み。施術時間が営業時間・一つの出勤区間に収まる場合のみ候補。
- `shifts` の `work` と有効な `staff_profiles` を必要とする。休憩は勤務区間を分割して登録。シフト未登録・休暇・休職・退職・二重シフトは空き枠にしない。
- キャンセル以外の予約・予定を除外。同時施術人数と担当者の重複を確認。他店に予約のある同じ担当者も空き扱いにしない。担当不明・店舗表記不明は保守的にブロック。
- 出勤区間の店舗は現在の店舗マスターIDまたは正式名称との完全一致が必要。旧略称データは事前に正規化すること。曖昧な名前で他店の勤務を使わない。
- 日付を横、時刻を縦とするカレンダー。○は空きあり、×は出勤枠があるが空きなし、－は所要時間／出勤／受付期限を満たさない枠。スマートフォンは横スクロールに対応。
- 公開メニューは店舗ごとに最大12件（名称・所要時間）。メニュー切替で再計算。料金・スタッフ指名は対象外。準備・片付け時間はメニューの所要時間に含める。
- ネット予約ONの場合、○→氏名・電話番号・情報利用同意→内容確認→確定。最新の空き状況とメニュー変更有無を再確認し、勤務中の担当者を自動割当。予約台帳の `reservations` に `source: public_booking`、`status: booked` で保存。既存顧客への自動紐付けは行わず、予約の連絡先として保存する。
- 完了画面に受付番号を表示。メール／LINE自動通知、電話番号の本人確認、セルフキャンセルは含まない。変更・キャンセルは店舗へ連絡する。外部のHot Pepper／SALON BOARDへ書き戻さない。
- 結果は取得時点の目安。画面の再読み込みで更新。外部予約はSALON AGENTに登録／取り込み済みのものだけ反映。重なりの数を保守的に数えるため、枠内で入れ替わる予約が多い場合は実際より空き枠が少なくなる場合がある。

## 保存と公開データ

追加のみ：`companies/{companyId}/availability_settings/{storeId}`（設定、共有トークン）、`public_availability_links/{sha256(token)}`（企業・店舗参照、有効状態）、`companies/{companyId}/availability_audit`（操作記録）。トークンは暗号学的乱数32バイト。管理操作で認証・企業・店舗所有・ロール・予約機能・企業稼働状態を検証。代理ログインからの変更は禁止。

公開APIはトークンから企業を決定し、予約・シフト・スタッフすべてをcompanyIdで限定。顧客コレクションは参照しない。JSONには店舗名、施術時間、更新日時、日付と開始時刻のみ。顧客名・予約詳細・スタッフ名／IDは含めない。DBエラーや件数上限では503とし、全枠空きとして返さない。no-store/noindex/no-referrer。公開画面で管理画面・AIサポート・フィードバック・ページ追跡を表示／実行しない。

## リリース前確認

1. Firestore indexesを反映し `shifts` と `reservations` の companyId＋date 昇順インデックス構築完了を待つ。
2. アプリをデプロイ。追加コレクションは既存のFirestoreクライアントアクセス拒否ルールに含まれる。
3. 店舗名とシフト店舗表記、出勤日、休憩、予約の取り込み状況、同時施術人数を確認する。
4. 管理者で保存→ログアウト端末で表示→既存予約と照合→停止／再発行後の旧リンク失効を確認する。
5. 公開APIは匿名アクセスのため、運用環境のWAF等でリクエスト制限・課金アラートを設定する。アプリでは取得期間を7日、予約／シフト各2000件、スタッフ500件までに制限。上限超過は503。公開ページは自動ポーリングしない。

コードの単体テスト・型検査・ビルドと、本番の認証／Firestore実データでの動作確認は別。実装作業では本番データの作成・変更は行わない。

## ネット予約の整合性と追加保存

`POST /api/availability/{token}/book` は同一Origin・JSONのみ、本文4096バイトまで。氏名・国内電話番号・同意・メニュー・日付・時刻をサーバーで検証。受付期間外、公開停止、企業停止、予約機能OFF、予約受付OFF、他社店舗、古いメニューは拒否。

予約作成、勤務／予約の再確認、担当者割当、冪等キー保存をFirestoreトランザクション内で実行。`companies/{companyId}/availability_booking_days/{date}` により同じ企業・日付のネット予約同士を直列化。既存の管理画面の手動重複入力許可や、外部予約システムの同時受付の仕様は変更していないため、他経路で後から追加する重複は店舗側で調整が必要。

`availability_booking_requests` はリンク＋リクエストIDで同一送信を識別し、同じ送信には同じ受付番号を返す。通信失敗時はフォームを固定し同一内容・IDで再送する。ページを閉じずに再送する案内を表示。氏名・電話番号は公開レスポンス／監査ログに含めない。

`availability_booking_limits` は店舗＋電話番号のハッシュをキーとし、30分で3件まで（同じリクエストの再送は消費しない）。これは本人認証やボット対策全般を代替しない。公開運用のWAF制限は引き続き必要。

追加したテストは単体・インメモリのトランザクション結合テスト。実Firestore／エミュレータでのロック競合試験や実端末の予約テストは別途リリース確認で実施する。本番での匿名予約は管理者がONにして初めて受付を開始する。
